# 场景与弹窗规范

本文规定页面、场景和弹窗的结构、跳转与可见性。

房间入口、退出和返回来源的完整要求见 [进出房间规范](./进出房间规范.md)。

## 结构

页面按需使用 `Background/Header/Sidebar/Content/Footer/Templates/Overlay`。不存在的区域不创建空节点。

- 运行时模板放在独立隐藏容器，不能混入列表内容或参与自动布局。
- 弹窗必须有唯一根节点和明确遮罩；关闭时同时移除交互、监听和资源。
- Scene、Prefab 和节点命名统一遵循 [命名规范](../命名规范.md)，本文不重复定义命名格式。
- 业务代码依赖登记过的稳定路径，禁止依赖兄弟序号、模糊查找或纯装饰节点。

## 进入界面

1. 先确认目标资源和必要数据可用。
2. 显示当前页面或统一过渡层，不得暴露空场景。
3. 加载并挂载目标界面。
4. 目标首帧完成后再移除旧界面和过渡层。

- 登录场景布局保持只读；账号登录弹窗中 `AccountInputInput` 与 `PasswordInputInput` 的 `cc.EditBox` 必须由场景外代码在面板激活后确保运行时实现已初始化、组件已启用，再延帧调用聚焦。序列化组件已失效但节点仍有效时，允许仅在运行时移除销毁残留并在原节点新建 EditBox、恢复现有文字/占位标签引用与输入参数；组件本身有效但 `_impl` 缺失时，只对现有组件执行一次性预加载/初始化。两种恢复都不得写回 `LoginScene.scene`、重复重建 DOM 或改变场景节点布局。
- 登录输入链当前同步状态（2026-09-10）：`LoginScreenBootstrap.ts` 的 `ensureEditBoxRuntime` 已同时覆盖“组件销毁残留”与“有效组件缺少 `_impl`/Web DOM”两类迁移状态，`LoginView.ts` 负责两个 EditBox 启用和延帧聚焦，登录单测通过。Creator 3.8.8 当前仍打开 `ClubDesk.prefab`，但标题已无 `*`，未保存阻塞已解除；须由责任岗位安全关闭该 Prefab、返回 `MainScene.scene`，再正常触发脚本重编译并确认 Preview chunk 更新。在该同步与真实登录复验完成前，CD201/LS201、QuickText 与亲友圈模板桌返回链均不得标记最终通过。

## 弹窗

- 打开弹窗不得切换到空场景，也不得先关闭当前界面再等待弹窗加载。
- 同一弹窗只能存在一个有效实例；重复点击不能叠出多个相同弹窗。
- 新弹窗出现前，旧弹窗按产品关系关闭或保留，禁止残留无关界面。
- 关闭后回到明确的上一层，不能出现黑屏、闪屏、穿透点击或多余页面。

## 场景跳转

- 所有跳转使用统一导航和过渡组件。
- 加载期间保持统一底色或品牌过渡，不出现黑帧、透明帧、旧场景闪回或半成品节点。
- 成功条件是目标根节点激活并完成首帧；失败时保留可理解的状态和重试入口。
- 重复跳转、迟到回调和旧请求不得覆盖当前场景。
- 返回路径必须唯一，不能同时保留旧场景和新场景的可交互界面。

## 修改要求

- 节点改名或换层级时同步更新代码契约。
- 调整前检查 Widget、Layout、Mask、ScrollView、坐标系和事件冒泡。
- 保留 `.meta` 与 UUID；修改后按 Creator 同步规范验收。

## 布局与适配

- 上下左右贴合、居中、锚点、尺寸、缩放、安全边距、排列、裁剪和常规分辨率适配，只要能由 Creator 的 `Widget`、`Layout`、`UITransform`、`Mask` 或 Prefab 表达，就必须在 Prefab 中配置；禁止在代码中重复计算坐标、强制移动节点、覆盖 Widget 或按分辨率写死偏移。
- 代码适配仅允许处理 Prefab 无法表达的运行时真实安全区、动态生成内容或平台实时数据；必须保留最小实现并注明无法使用 Prefab 配置的具体原因。发现可迁回 Prefab 的历史代码适配时，删除对应代码并同步到 Prefab，不得保留双重适配。

## 跑得快公共房间布局契约

- `Client/assets/Games/Common/Scenes/GameRoom2D.scene`是跑得快公共房间画布和固定层布局的序列化权威：Canvas设计尺寸为`1280×720`，各固定层的`UITransform`和Canvas Widget状态由场景表达。
- `GameRoom2D` 随父目录唯一 Bundle `games-common` 发布；场景加载器必须通过该 Bundle 的 `preloadScene/loadScene` 进入房间。`assets/main/config.json` 不包含该场景属于正常边界，不得据此恢复旧场景或把它复制进主包。
- `CommonPdkGameSceneLauncher`只负责场景启动与业务挂载，不得在运行时对GameRoom2D的Canvas或各固定层调用`setContentSize`、`setPosition`，也不得禁用其Widget进行常规适配。
- `Client/assets/Games/Common/Prefab/ChatPanel.prefab` 的根 Widget 负责弹窗居中；聊天、语音和解散等公共房间 Prefab 均由父级 `games-common` Bundle 加载，`Games/Common/Prefab` 子目录不得再声明嵌套 Bundle。
- `PDK_CommonRoom/Btn` 是房间根节点的直接末层，用于保证按钮不被玩家位或其他触摸节点遮挡；节点层级调整后必须按渲染相机 `worldToScreen` 的真实屏幕坐标执行 Canvas 点击验收，不得用设计坐标或内部函数调用替代。
- `CommonPdkChatController`不得在运行时禁用或覆盖 ChatPanel 根 Widget。
- ChatPanel展开与收起动画只移动`Popup`、`EmojiGrid`、`QuickTextPanel`等内容子节点，不得移动根节点或改写根布局契约。

## 亲友圈桌子预制体样例契约

- 样例唯一位于 `Client/assets/Club/Prefab/test/ClubDesk.prefab` 与同目录独立嵌套的 `ClubDeskSeat.prefab`；两者只用于 Creator 结构样例，未接入正式 Prefab、业务脚本或运行时流程。
- `ClubDesk` 固定包含长桌 6 至 12 人、圆桌 2 至 5 人、方桌 2 至 4 人共 14 套独立 `PlayersN` 布局；每套布局使用 `Positions` 保存与人数相同的语义位置，每个位置直接嵌套一个 `ClubDeskSeat` 实例，总计 86 个位置与 86 个嵌套实例。
- `ClubDeskSeat` 只保留 `Top/Bottom/Left/LeftTop/LeftBottom` 五个原始方向，不创建 `Back/Front/Side` 平行命名；右侧 `Right/RightTop/RightBottom` 及编号位置复用相应左侧视觉并使用 `scaleX=-1` 水平镜像。
- 五个方向的椅子 SpriteFrame 使用现有 Club Atlas：`Top=chair_5_3`、`Bottom=chair_5_2`、`Left/LeftTop/LeftBottom=chair_5_1`；`PlayerState/AvatarMask/Avatar` 使用 `icon_tx46` 作为可被运行时替换的默认头像。预览默认显示玩家态、隐藏空位态，不得在 `PlayerAnchor` 重复添加头像结构。
- 两份 Prefab 必须保持独立与原 UUID，不得把座位展开为普通节点。调整后须由 Creator 3.8.8 重新导入、分别重开并检查层级、镜像、Missing Node 和反序列化错误，保存关闭后释放编辑态。
