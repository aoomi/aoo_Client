# 命名规范

本文只规定 Scene、Prefab、节点、业务层级目录及 UI 图片资源的命名，不规定节点层级结构、布局或适配。

## 基本原则

- 名称必须非常精简且语义明确，以 AI 能结合所在目录和父级上下文直接理解功能为准；优先使用短英文词或通用缩写，禁止堆叠冗长词组、重复上下文、无意义前后缀或自造缩写。
- 同一功能只使用一个最短且无歧义的名称。示例：`CompensationAdjustmentTemplate` 精简为 `CompAdjust`，`OperatorClubName` 精简为 `OpClubName`。
- Scene、Prefab、节点和业务层级目录统一使用首字母大写的 PascalCase；除本规范明确规定的类型分隔和数字后缀外，不使用下划线。
- 末尾需要数字编号时统一使用 `_数字`，不得把数字直接连在名称后；例如 `Background2` 改为 `Bg_2`，`DeltaSep2` 改为 `DeltaSep_2`。
- 稳定业务编码保持既定大写格式，不因视觉命名规则产生别名。

## 节点类型命名

- 所有实际按钮节点统一命名为 `Btn_<Action>`，例如 `Btn_Back`、`Btn_CreateRoom`；不得使用无 `Btn_` 前缀的按钮名。多个按钮的共同父节点仅承担按钮集合职责时，统一命名为 `Btn`；普通父节点不得仅因包含按钮而强制改名为 `Btn`。
- 同一父节点下只有一个文字组件时，该文字节点统一命名为 `Label`；同级存在两个或以上文字组件时，各文字节点统一使用 `Lb_<Meaning>`，例如 `Lb_Name`、`Lb_Score`。
- 图标显示节点统一使用 `Icon_<Meaning>`，例如 `Icon_Club`；不得使用含糊的 `Sprite`、`Image` 或无用途名称。
- 整屏场景遮罩统一命名为 `Mask`。
- 房间、大厅等整屏背景图节点统一命名为 `Bg`。
- 其他局部小遮罩或小背景节点统一使用 `Bg_<Meaning>`；存在编号时写成 `Bg_<Meaning>_数字`。
- 未在本节明确规定类型前缀或分隔符的节点，使用精简 PascalCase，不额外添加 `_`。

## 代码与消息命名

- “消息”的统一英文简写为 `Msg`。文件、目录、类、接口、DTO、组件、Prefab、节点、方法和字段中的消息语义统一使用 `Msg`；lowerCamelCase 变量或字段使用 `msg`，常量按项目格式使用 `MSG`。旧协议字段、外部 SDK 字段、数据库历史列名或已发布资源键不能直接改名时，必须通过集中兼容映射接入，不得扩散到新增内部代码。
- 代码、脚本、类型、接口、DTO、枚举、事件、方法、字段、序列化属性、配置键和资源键必须精简、语义准确且格式一致。禁止使用 `New`、`Copy`、`Temp`、`Other`、`Misc`、`Manager2`、数字版本后缀、无意义缩写、同义混用、重复上下文或与实际职责不符的名称；测试代码和明确属于测试的文件可以使用 `Test`。
- Prefab 文件名、根节点名、主组件类名和脚本名应保持可追溯的一致语义，但不要求机械同名；公共组件不得带具体页面或玩法名称，专属组件不得使用伪装成公共能力的宽泛名称。

## 业务术语映射

- 用户沟通中的“亲友圈”和“俱乐部”表示同一业务域；AI 接收任一说法时都必须自动映射为代码层的 Club 语义，不得要求用户改用固定称呼。
- 代码、类、文件、目录、节点、Prefab、配置键和新增协议标识统一使用 `Club` 或既有 `club` 命名空间；禁止新增 `QinYouQuan`、`Qinyouquan`、`PYQ`、拼音或其他平行代码名称。
- 例如用户说“增加一个亲友圈按钮”，代码和节点名称应使用 `Btn_Club...`，不得写成 `Btn_QinYouQuan...`。界面展示文案仍按用户指定的“亲友圈”或“俱乐部”显示，不用代码命名反向改变产品文案。
- 本规则适用于新增名称及用户明确要求修改的范围；不得借术语统一擅自批量重命名用户未明确点名的现有代码或资源。

## UI 图片资源命名

### 基本格式

- 文件名按 `[类型]_[功能/用途]_[对象]_[方向]_[规格]_[状态]` 从大类到细节组合，非必填段直接省略；状态存在时必须位于最后。
- 全部使用小写英文和下划线；禁止中文、拼音、空格、特殊符号、哈希前缀，禁止 `new`、`old`、`final`、`test`、`temp`，禁止无意义的 `img`、`pic`、`texture` 和无语义数字。
- 名称至少回答“图片类型”和“功能用途”；存在状态或方向时，还必须明确状态或方向。
- 节点名称与图片文件名属于不同命名域：按钮节点可为 `Btn_CreateRoom`，对应图片仍为 `btn_room_create_normal.png`；禁止互相套用大小写格式。

### 类型词

- 容器与背景：`bg` 页面或游戏背景，`popup` 弹窗背景，`panel` 面板，`list_bg` 列表背景，`item_bg` 列表项，`input_bg` 输入框，`tip_bg` 提示框，`bubble_bg` 气泡，`mask` 遮罩，`overlay` 全屏覆盖。
- 按钮与图标：`btn` 完整按钮，`btn_bg` 按钮底图，`btn_icon` 图标按钮，`icon` 功能图标。
- 头像与标识：`avatar`、`avatar_frame`、`avatar_mask`、`avatar_status`；`frame` 通用边框，`badge` 小型身份或角标，`tag` 文字标签，`status` 业务状态。
- 文字与导航：`title` 美术标题，`text` 固定美术字，`number` 数字图；`tab`、`nav`、`menu`。
- 选择与输入：`checkbox`、`radio`、`toggle`、`slider_track`、`slider_fill`、`slider_thumb`、`dropdown`、`scrollbar`、`page_indicator`。
- 进度与加载：`progress_bg`、`progress_fill`、`loading`、`arrow`。
- 牌桌与玩法：`table`、`chair`、`seat`、`card`、`tile`、`hand_type`、`game_logo`。
- 特效与装饰：`fx`、`deco`、`light`、`shadow`、`glow`。

### 状态、方向、颜色与规格

- 状态词只允许 `normal`、`pressed`、`selected`、`unselected`、`disabled`、`hover`、`focused`、`active`、`inactive`、`locked`、`unlocked`、`on`、`off`；不得混用同义词或缩写。
- 方向词只允许 `top`、`bottom`、`left`、`right`、`left_top`、`right_top`、`left_bottom`、`right_bottom`；禁止使用 `up`、`down`、`lt` 等别名。右侧资源可由左侧资源镜像得到时，不得复制图片。
- 颜色词只允许 `red`、`orange`、`yellow`、`green`、`blue`、`cyan`、`purple`、`gray`、`black`、`white`、`gold`。仅当相同用途必须依靠颜色区分时才添加；颜色表达业务含义时，优先使用 `confirm`、`cancel`、`success`、`warning` 等功能用途。
- 尺寸默认不写入文件名；确有多规格时使用 `small`、`medium`、`large` 或明确像素，例如 `avatar_frame_64`，不得使用 `sm`、`s` 等自造缩写。
- 九宫格标识只允许后缀 `_9slice`。
- 序列帧编号统一为两位补零并放在末尾，例如 `fx_coin_01`、`loading_spinner_01`。

### 文字、目录与去重

- 普通文字必须由 Cocos `Label` 渲染；只有固定美术字图片才使用 `title`、`text` 或 `number` 类型命名。
- 优先按功能建立子目录并保持文件名简短；目录已表达功能时，文件名不重复完整目录含义。资源平铺在 `Texture` 或 `Atlas` 时，文件名必须增加功能前缀避免冲突。
- 同一目录不得存在同名、同用途的重复图片。
- 积分记录资源位于独立子目录时，可使用 `panel.png`、`badge_match.png`、`badge_remaining.png`、`arrow_green.png`、`frame_green.png`、`arrow_orange.png`、`frame_orange.png`、`arrow_blue.png`、`frame_blue.png`；平铺时必须增加 `score_record_` 前缀。

## 变更边界与验收

- 新增对象和用户明确要求修改的名称必须遵守本规范；用户没有明确点名修改的现有 Scene、Prefab、节点、目录和图片名称，不得擅自重命名或借任务顺带清理。
- 重命名前必须确认准确对象和授权范围，并检查全部代码路径、序列化引用、动画轨道、事件绑定、动态加载路径和测试契约。
- 获得明确授权并完成重命名后，必须保留原 `.meta` 与 UUID，同步所有引用和 Creator 资源数据库，重新打开目标 Scene 或 Prefab 验证；不得保留新旧并行名称或兼容别名。
