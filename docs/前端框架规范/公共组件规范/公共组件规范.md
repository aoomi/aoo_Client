# 公共组件规范

本文只回答“哪些能力必须统一”。业务页面只传数据、资源和回调。

## 全局公共组件

- 页面导航、弹窗、Loading、Toast、按钮、Tab、输入、选择和安全区适配。
- 虚拟列表、分页、空状态、头像、远程图片、倒计时、红点和对象池。
- HTTP/WebSocket、Bundle 下载、配置、本地存储、音频、日志、权限和多语言。
- 全局公共 Prefab 只允许从 `common` 的六项权威清单加载：`CommonHead`、`MsgDrift`、`Message`、`Numpad`、`SettingsPanel`、`WaitNet`。逻辑别名必须收敛到这六项，禁止恢复历史副本或把牌局公共 Prefab 混入。

## 牌局公共组件

- 玩家位、网络状态、托管、聊天、退出、解散、房间错误和结算控制。
- 创建房间统一使用规则表单组件；业务只提供字段定义和默认值。
- 公共房间聊天、语音与解散 Prefab 统一从 `games-common` 加载，不得由具体玩法复制或通过已废弃的嵌套 Bundle 兼容。
- 房间微信邀请与分享在网页端复制房间信息并给出成功提示，在 App 端直接发起微信分享；不得重新依赖用户已删除的历史分享面板。
- 快捷文字只有在真实按钮点击产生唯一请求且另一客户端收到服务端广播并展示后才算验收通过；仅本端发出请求不能替代跨客户端送达证据。

## 公共化条件

满足任一条件就应公共化：三处以上复用；涉及网络、安全或性能；需要全项目统一体验；需要后台配置。

完全不同的牌桌交互或独有动画可以留在玩法内，但仍必须使用公共网络、资源、导航、加载、日志和适配能力。

## 性能底线

- 长列表只创建可见项和少量缓冲项。
- 图片请求限并发，节点回收时取消，复用时校验数据版本。
- 对象池必须有上限并随页面清理。
- 下载、解码和 Prefab 实例化分帧执行，实时牌局消息优先。
