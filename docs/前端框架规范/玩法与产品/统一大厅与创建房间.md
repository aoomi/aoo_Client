# 统一大厅与创建房间

本文只描述产品结构，不规定底层架构。

## 页面结构

- 大厅展示常用玩法、最近使用和创建房间入口。
- 创建房间页分为玩法选择、规则选择和创建操作三部分。
- “更多玩法”使用独立弹窗，按地区和牌类筛选，不与主规则区混排。

## 玩法选择

- 玩法名称和地区身份必须唯一，不能用相近玩法别名代替。
- 常用玩法只影响展示顺序，不改变玩法规则。
- 切换玩法后加载该玩法自己的规则，旧玩法选择不得残留。

## 规则表单

- 单选、多选、开关、数字和条件项使用统一控件。
- 默认值、可选项、禁用态和联动来自权威规则配置。
- 隐藏规则仍由服务端锁定，不能只靠前端隐藏。
- 创建前展示最终选择摘要；创建中禁止重复提交。

## 结果

- 创建成功后进入对应房间。
- 配置过期、资源缺失或创建失败时留在当前页面并给出明确提示。
- 关闭弹窗或返回大厅时，不保留多余界面、遮罩或未完成请求。

## 亲友圈入口可见性

- `btn_caseSprots` 保险箱入口在进入普通亲友圈和赛事大厅时均默认显示，不受 `unionId`、用户权限或赛事状态控制。
- “更多”面板仅负责现有入口组的展开与收起，不得把保险箱默认可见性重新绑定到模式或权限判断。

当前实现状态（2026-09-11）：`LegacyClubMainController.applyClubModeVisibility` 已在每次进入普通亲友圈或赛事时显式启用保险箱入口，专项测试 `club-box-default-visibility.test.mjs` 通过；因 Creator 3.8.8 项目窗口被同版本启动器模态窗口遮挡，Preview 尚未刷新，真实 Canvas 终验待编辑器窗口恢复后完成。

## 俱乐部成员邀请

- 用户沟通中的“亲友圈成员”与“俱乐部成员”是同一业务含义，代码和协议统一使用 Club 命名。
- 管理者输入并确认玩家 ID 后，`club.CClubFindPIDAdd` 必须在同一服务端事务中直接新增正式成员，不再创建七天有效或需要目标玩家接受的待处理邀请。
- 新成员的 `upPlayerId` 必须写为本次邀请操作者的玩家 ID，表示成员直接归属邀请人；该玩家已有的待审核 JOIN 申请须在同一事务中移除。
- 请求字段保持 `clubId + pid`；成功响应明确返回 `joined=1`、`playerId`、`upPlayerId` 和 `member`。客户端成功提示和成员列表刷新必须按“已直接加入”处理，不得继续展示等待接受状态。

当前实现状态（2026-09-11）：Club 服务定向集成测试 `4/4`、客户端提示专项测试 `1/1` 通过，Creator 脚本导入无新增错误，Hall 健康；未使用真实账号新增测试成员，避免污染用户现有俱乐部数据。

## 亲友圈模板房流程

1. 在亲友圈大厅点击“房间管理”。
2. 打开赛事房间管理的玩法页`btn_Wanfa`，不得直接跳到创建房间规则页。
3. 玩家点击“添加玩法”后，才打开创建房间规则页。
4. 选择玩法和规则后点击`Create_Room.prefab`中的`MainPanel/Actions/btn_next`（显示文字“下一步”），填写房间名称、入场分数等赛事参数；赛事模式仅显示`btn_next`，非赛事模式显示`CreateButton`。
5. 保存时提交`union.CUnionCreateRoom`。
6. 保存成功后关闭房间管理链路，并调用`union.CUnionGetAllRoomMin`刷新亲友圈大厅模板桌。

- 赛事/联盟大厅模板桌的权威数据源为 `union.CUnionRoomConfigItemList`，普通亲友圈大厅模板桌的权威数据源为 `club.CClubRoomConfigItemList`；大厅进入、亲友圈切换及模板保存后的刷新必须使用对应模板配置列表。
- 模板配置项须兼容权威 `configId` 与 `size` 字段。游戏中房间列表只表示正在运行的房间，不能作为空闲模板桌数据源；其全量推送即使为空，也不得清空或覆盖模板配置列表。

当前实现状态（2026-09-10）：`ClubDispatchService`已接通`union.CUnionRoomCfgList`、`union.CUnionRoomCfgCount`、`union.CUnionCreateRoom`和`union.CUnionGetAllRoomMin`，通过权威`JdbcClubService`持久化模板并校验赛事ID与管理员权限；稳定业务编码`CD201`解析为历史代理键`gameId=201`。`JdbcClubServiceIntegrationTest`已覆盖“创建赛事模板→管理列表/统计→亲友圈大厅读取”，Club影响模块测试通过，Gateway已单模块重建并重启，核心端口健康。此前`3008: unsupported union action`阻塞已解除。客户端只绑定用户指定节点`MainPanel/Actions/btn_next`；上下文或规则未就绪时显示明确提示，不再静默返回。Creator 3.8.8已刷新资源，账号`31`已真实点击“房间管理→添加玩法→下一步→保存”，服务端成功处理`union.CUnionCreateRoom`并调用`union.CUnionGetAllRoomMin`刷新，返回大厅后显示`CD201`模板桌；专项测试`1/1`、Creator原生资源门禁`blocking=0`。该保存与模板桌刷新流程已完成真实验收，不得再沿用此前画布命中阻塞结论。

## 亲友圈模板桌入房与返回

- 点击模板桌进入房间时，必须保留 `CLUB/UNION` 来源及当前亲友圈上下文；房间内通过 `Btn_Menu`→`Btn_Back` 返回后，必须恢复原亲友圈大厅、房间列表与按钮交互。
- 返回链不得让已销毁的 Lobby/Club 控制器继续执行延迟回调或解绑空节点；不得出现 `LegacyFormManager 已销毁` 或对 `null` 执行 `off` 的异常。
