# 玩法规则文档规范

## 1. 适用范围

- 本目录按玩法分类建立子目录，例如`跑得快/`、`麻将/`、`斗十四/`、`升级/`、`牛牛/`、`考考/`；禁止把地区规则散放在根目录。
- 同一玩法的公共规则、地区规则和目录`README.md`全部存入该玩法子目录。
- 每个地区、每个玩法单独一份文档，文件名统一为“地区名+玩法名+规则.md”；公共文档统一为“玩法名+通用规则.md”或已有正式公共命名，不得并存同义副本。
- 公共规则只维护一份公共规则文档；地区文档必须明确引用公共规则并重点记录地区真实差异，禁止复制多份后分别维护。
- 玩法流程必须融合进对应地区玩法规则文档，不得同时维护内容重复的独立流程正文。
- 已有独立流程文档完成迁移后只保留简短迁移说明和正式规则索引；确认无其他引用后由aoo产品决定是否删除，不得直接删除。

## 2. 固定章节

所有玩法规则文档必须保留以下章节及顺序；没有内容时写“无”或“待确认”，不得删除章节：

1. 基本信息
2. 牌组与发牌
3. 开局与庄家
4. 游戏目标与结束条件
5. 游戏流程
6. 操作规则
7. 牌型或胡牌规则
8. 特殊牌型
9. 术语
10. 计分与结算
11. 开房配置
12. 界面与展示要求
13. 当前实现差异
14. 待确认事项
15. 权威来源

## 3. 内容规则

- 用户最新明确规则优先；开房配置以对应规则表为唯一权威来源。
- 已确认规则、配置表定义、当前代码实现和待确认内容必须分开记录，不得混写。
- 只精简重复、口语和明显错别字，不得改变数字、条件、优先级或业务含义。
- 原始规则存在矛盾、缺项或疑问时，正文保留已确定部分，疑问集中写入“待确认事项”，不得自行推断。
- “开局与庄家、游戏目标与结束条件、游戏流程、操作规则”必须互相衔接，形成从开局到结算及下一局的完整可执行流程。
- 规则变更应修改原文档，不得另建“新版”“最终版”等重复副本。
- 明确适用于该玩法全部地区、默认所有新地区继承，且属于通用牌型、流程、协议术语或基础结算的内容，写入该玩法唯一公共规则。
- 仅适用于特定地区的配置、例外、当地叫法、特殊牌型、计分或流程差异，只写入对应地区规则。
- “默认关闭、某地区开启”时，默认策略写公共规则，地区启用事实写地区规则。
- 地区文档只引用公共规则，不复制公共正文。
- 多地区相同但并非全部地区适用时，不直接提升为公共规则；分别引用共享能力说明，或在唯一正文中明确列出适用地区。
- 用户最新规则未明确范围时，结合上下文、只读规则表和现有权威文档判断；仍无法确定则写入“待确认事项”并报告aoo产品，不得猜测。
- 修改公共规则前检查全部地区影响；修改地区规则不得改变其他地区。
- 同一规则只保留一个权威正文，目录索引和交叉引用必须随文件移动或内容归属同步更新。
