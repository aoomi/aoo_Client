# 客户端屏幕适配职责迁移审计

## 审计结论

- 对 `Client/assets/**/*.ts` 中尺寸、坐标、锚点、缩放、`Widget`、`Layout`、可见区域与安全区调用进行只读清点，共命中 627 个候选位置；候选包含业务动画和牌桌排布，不能机械迁入 Prefab。
- 静态界面适配的主要集中风险为 `LegacyFormManager.adaptLegacyFullscreenForm()` 与 `LegacyLobbyScreen.refreshLobbyDirectionalLayout()`：运行时改写全屏表单尺寸、缩放、背景尺寸、方向容器 Widget 和位置。这些属于可逐页迁回 Creator 3.8.8 Prefab 的候选，但迁移会改变现有大厅及公共表单视觉，必须在前置真实房间验收完成后按页面串行处理。
- `CommonPdkGameSceneLauncher.prepareGameCanvas()` 固定游戏 Canvas 与七个图层为 `1280×720`，属于场景初始化契约；在游戏 Scene 尚未完成 Creator 权威布局迁移前必须保留，不能直接删除。
- `SafeAreaAdapter` 根据运行设备 `visibleSize` 与系统安全区实时计算尺寸和位置，属于必须保留的动态平台适配，不应固化进 Prefab。
- 牌桌座位、手牌、提示、动画和动态列表运行时坐标属于业务状态呈现，不纳入静态布局迁移。
- `LoginScene.scene` 为用户维护的唯一视觉权威；登录代码仍有运行时尺寸、锚点和位置写入候选，但本岗位只记录，禁止改写该 Scene 或用脚本迁移其布局。

## 安全恢复点

- 本轮只新增审计证据，没有修改屏幕适配代码、Scene、Prefab 或规则表。
- 待公共头像、缓存进入、ChatPanel、SettingsPanel 的真实房间验收闭环后，从 `LegacyFormManager` 的单页表单分类开始；每批只迁一个界面，完成 Creator 重导入、重新打开、桌面与移动真实 E2E 后再进入下一批。
