# Widget 动态适配专项审计清单与计划

## 扫描范围与口径

- 范围：`Client/assets` 下全部 TypeScript、JavaScript 与验收脚本。
- 命中条件：运行时创建、销毁、禁用或刷新 `Widget`；写入四边、中心或 `alignMode`；按可见区域修改 `UITransform` 尺寸、节点坐标或缩放。
- 判定：常规分辨率适配能由 Prefab/Scene 的 `Widget`、`Layout`、`UITransform`、`Mask` 或层级表达时必须迁回资源；真实安全区、运行时动态内容和数据驱动渲染允许保留最小代码。
- 边界：`LoginScene.scene` 严格只读；NJ201 已冻结；已冻结业务与其他岗位正在修改的文件先报告冲突，不并发写入。

## 初始分类

### A. 明确需要迁回 Prefab，但当前存在职责或冻结冲突

1. `Club/Code/Runtime/LegacyClubLandscapeAdapter.ts`：强制根节点 `1280×720`、归零坐标/缩放、覆盖背景尺寸、禁用 Widget、运行时夹紧关闭按钮并递归 `updateAlignment()`。这些属于常规四向布局；应迁回各亲友圈 Prefab。文件与资源由亲友圈岗位负责，本线程不写。
2. `Games/Poker/PDK/Common/Code/Runtime/CommonPdkGameSceneLauncher.ts`：运行时改 Canvas/层尺寸与坐标并禁用 Canvas Widget。涉及正在执行且已冻结的跑得快房间链；须先与玩法岗位确定权威 Scene/Prefab 后迁移。
3. `Games/Poker/PDK/Common/Code/Runtime/CommonPdkChatController.ts`：首次显示时强制 `updateAlignment()` 后禁用 Widget，并按可见宽度计算隐藏位置。滑入动画可保留，但最终显示位置应由 Prefab Widget 决定；涉及已冻结 ChatPanel 接线与正在执行的跑得快代码，先报告冲突。
4. `Common/Code/Runtime/CompatibilityApp/*SceneBootstrap.ts`：`a3pk`、`aycp`、`aydss` 销毁 Widget 后按屏幕缩放；`afmj`、`ahhbmj`、`ahhnmj`、`ahmj`、`ak159mj`、`aqmj`、`asmj`、`aymj`、`bamj`、`bdjhmj`、`scjymj` 与 `Games/Mahjong/Packs/Pack01/.../hzmj` 按 `view.getVisibleSize()` 改根缩放/坐标。均属于常规设计坐标适配，应逐个迁回对应原生 Prefab；范围跨多个玩法且现有资源验收状态未知，先串行建立资源映射，不做批量机械改写。

### B. 公共层明确需要拆除的历史全屏覆盖

1. `Common/Code/Runtime/ui/LegacyFormManager.ts`：根据设计尺寸统一缩放根节点、禁用根/背景 Widget、改背景尺寸与坐标，并对亲友圈路径特殊处理。它会覆盖所有 Prefab 的序列化布局，是本专项的公共根因之一。必须先建立每个调用路径与实际 Prefab 清单，再按页面分批迁移；不能一次删除导致未迁移页面失去布局。

### C. 合法保留

1. `Common/Code/UI/SafeAreaAdapter.ts`：读取平台实时安全区并设置承载节点尺寸/位置，Prefab 无法预知，保留。
2. `Common/Code/Runtime/ui/LegacyPrefabRenderer.ts`：从运行时权威 Manifest 创建动态节点并还原其序列化 Widget、尺寸、锚点和坐标；属于数据驱动节点生成，不是对已有 Prefab 二次适配，保留。
3. `Common/Code/UI/CommonHeadController.ts`：按头像相对当前可见中心决定聊天气泡方向，属于运行时座位真实位置数据，不承担常规四边布局，保留。
4. `Games/Poker/PDK/Common/Code/Runtime/CommonPdkPlayController.ts` 的手牌可见宽度、动态牌节点、飞行动画和触摸坐标；`Common/Code/UI/UnifiedScroll.ts`、`Lobby/Code/Runtime/CreateRoomRulePresenter.ts` 的动态内容尺寸/排列：均由运行时数据量决定，保留，但后续检查不得混入固定屏幕边距。

### D. 只读或非适配命中

1. `Login/Code/**`：命中固定 UITransform/坐标，但登录布局受强制只读约束；只记录，不修改。
2. 其余 `setContentSize/setPosition` 多为动态列表、牌张、动画、临时提示和运行时创建节点，不属于四向分辨率适配；保留原业务行为。

## 执行计划

1. 先处理公共 `LegacyFormManager`：建立所有 `adaptLegacyFullscreenForm` 路径、Prefab 尺寸和 Widget 序列化清单，选取不属于登录、亲友圈、PDK 冻结范围的首批页面迁移。
2. 对每一批 Prefab 仅调整已有 Widget/UITransform，不改业务节点层级和命名；删除对应代码分支，禁止双重适配。
3. CompatibilityApp 按玩法逐个映射 SceneBootstrap 到原生 Prefab，确认资源 UUID 和当前岗位授权后串行迁移；无明确资源或玩法归属时保持待办，不猜测。
4. 亲友圈、PDK、ChatPanel 职责明确时直接点对点交接；存在同文件或共享状态冲突、需要统一优先级或授权时才交由aoo产品协调，获得明确文件写入权与安全断点后再处理。
5. 每批 Prefab 由 Creator 3.8.8 正常重导入并重开，检查控制台、资源引用、TypeScript 和相关门禁；最后用专属 CDP `1234` 对同一 Preview 做桌面、宽屏、移动触摸真实验收。
