## 0. 执行边界

1. 必须完整读取根 `AGENTS.md`、第 3.1 节列出的本岗唯一入口、公共 5 份规范和本岗额外必读；不得用“现行项目规范”“指定提示”代替清单。当前规范与代码为准，历史只作追溯。
2. 先建责任面清册和证据快照，再做静态只读审计。未获独立授权，不运行完整构建、Creator、真实 E2E、压测、攻击/灾备/发布演练或任何写操作。
3. 仅审本岗目录、模块和直接调用链；跨域只读确认依赖并登记线索，不代审。
4. **禁止**修改、新建、删除、移动、重命名、格式化或重存源码、配置、文档、数据、Scene、Prefab、`.meta`、资源、规则表及 AI 员工记录；禁止顺手修复、恢复旧文件、重导 Creator 资源或把建议当整改授权。
5. 排除 `node_modules`、`Library`、`temp`、`build`、`target`、日志、备份、生成物、第三方源码及 `Server/reference`；仅确认生成物被误作源码依赖时纳入。供应链只审项目选择、锁定、接入和发布责任。
6. 结论只输出到当前对话或获准报告位置；用户明确授权具体整改后，才可另行修改并验收。

## 1. 单一公共取证与判定合同

每个流程/问题必须同时追踪：客户端 Scene/Prefab/组件/状态/网络 → 协议 → Gateway/路由 → 服务端 Controller/Handler/领域服务 → 缓存/MQ/DB/事务 → 响应回写 → 失败恢复 → 测试。只找到一端不得结束；纯客户端、纯服务端或离线工具必须写“无对应端”及原因和边界证据。任一端缺失、重复、权威不一致或目录层级不对应，必须列问题或待确认。

报告头必须记录审计时间、Client/Server/Admin 仓库或等价快照指纹、关键清单哈希、读取规范、命令/版本/退出码、证据生成时间和过期条件；无法取得时标 `UNVERIFIED`，不得伪造。

每张矩阵必须声明分母来源（实际目录与注册表、路由、序列化、构建、部署入口的并集）、快照指纹、去重键、排除项及理由。状态只能是 `PASS/FAIL/PARTIAL/UNVERIFIED/NOT_APPLICABLE`；N/A 必须有边界证据，空值不得当 PASS，“未发现”不等于“已证明不存在”。证据等级区分静态定义、注册/调用链、自动测试、运行配置、真实入口/演练，并记录新鲜度、反例和缺口。

`静态只读审计完成` 仅表示分母闭合、源码/配置/既有证据已审、动态项列未验证和后续计划；`运行闭环通过` 必须另行授权并真实验证。前者**不得**写成上线通过。

不得凭文件名、长度或单匹配下结论；每项追定义、调用者、状态源、清理与测试并排误报。同根因表象合并；重复至少两处；删除建议先排动态加载、反射、序列化、协议注册和运维脚本引用。只报有文件行号、触发和实际影响的事实；不确定项列待确认和缺证，不提高严重度凑数。

P0=安全/资金/数据毁损或大面积不可用；P1=核心功能错误、生产无界循环、关键闭环缺失或上线阻断；P2=局部功能、性能、维护性风险且有明确影响；P3=低风险质量问题。不得改义。

报告、命令输出、截图和附件必须去敏，只留类型、位置、哈希/掩码、最小摘要和受控引用；不得复制密码、Token、Cookie、密钥、生产连接串、完整隐私、暗牌、牌墙、原始随机种子或完整账务明细。疑似秘密立即停止扩散并标高风险。

新增闭环定位：<a id="C01"></a>`C01`=审计身份/版本/新鲜度；<a id="C02"></a>`C02`=互斥状态与证据等级；<a id="C03"></a>`C03`=分母来源与差异对账；<a id="C06"></a>`C06`=报告脱敏；<a id="C08"></a>`C08`=静态审计/运行闭环两阶段。上述定位分别由本节对应强制段落完整承接。

## 2. 责任面与跨岗协作

- <a id="G01"></a>`G01`：以岗位职责、生产入口和发布目录生成 `scopeId`；每项唯一主审，可列协审但不得重复主审。未分配、重复主审、未知归属任一非零，不得称全项目完成。框架、登录大厅、亲友圈、跑得快之外，麻将、扯旋、牛牛、金花及其他实际发布玩法必须逐一分配，不得写“其他玩法类推”。
- <a id="G02"></a>`G02`：逐后台菜单/路由/API/Handler 标业务 Owner 与框架 Owner；业务后台随业务岗位，公共认证、RBAC、菜单路由、审计日志、发布控制面归框架。无人归属或多主审进入阻塞清单。
- <a id="C04"></a>`C04`：统一 `scopeId/findingId/lineageId`、主审/协审/接收岗位、证据引用和状态。发送方只登记线索，结论只由主审下达并按根因去重；未接收、冲突、重复主审或无人归属任一非零，不得报全局完成。

四个原岗位必须保留：框架主审公共客户端/服务端框架、协议/Gateway/Bootstrap、公共房间与账本、配置中心、构建发布、基础设施和后台公共控制面；登录大厅主审登录、认证、账号、身份、Catalog/大厅及相关后台；亲友圈主审圈子、成员/权限、模板、桌子/战绩/计分及相关后台；跑得快主审其 Client/Server/协议/规则/资源/回放/结算及相关后台。精确范围、排除和专项以第 4 章冻结岗位表为准。
