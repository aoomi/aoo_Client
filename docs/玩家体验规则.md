# 玩家体验规则

## 1. 目标

在不操控发牌、不指定胜负、不破坏玩法公平性的前提下，通过合理匹配、分层引导和对局复盘，改善玩家的长期游戏体验。

## 2. 统计范围

- 游戏大厅作为一个独立统计域。
- 每个亲友圈作为一个独立统计域，不得将某个亲友圈的输赢或行为数据直接用于另一个亲友圈。
- 统计维度应至少包含：`scope_type`、`scope_id`、`player_id`、`game_code`和统计周期。
- `game_code` 必须使用项目统一的稳定业务编码。

## 3. 玩家画像

可记录与体验优化直接相关的聚合指标：

- 长期胜率、平均得分、连胜和连败次数。
- 出牌大小倾向、风险偏好、稳健度和激进度。
- 对局时长、中途离开率、托管率和重新开局率。
- 画像必须由可解释的历史数据生成，不得使用敏感个人信息推断玩家性格或现实身份。

## 4. 体验优化规则

- 按玩家水平、活跃度和出牌风格优化组桌，提高对局匹配度。
- 对新玩家提供新手引导、规则提示和渐进难度，但不改变随机发牌规则。
- 玩家连败或频繁中途离开时，可推荐低压力房间、玩法教程或对局复盘。
- 陪练机器人必须明确告知玩家，不得伪装成真人。
- 任何体验策略都只能影响匹配、提示、教学和展示，不得影响牌序、发牌、抽牌、结算或胜负判定。

## 5. 公平性红线

- 禁止按玩家身份、充值、连胜、连败或运营指令调整牌序和胜率。
- 禁止为指定玩家、亲友圈或房间设置暗控输赢参数。
- 禁止将玩家画像接入发牌、结算、回放或计费逻辑。
- 随机数、发牌和结算过程必须可追溯、可审计，且不得在对局中被运营后台修改。

## 6. 数据与隐私

- 只收集实现上述功能所必需的数据，并设置明确的保留期限。
- 玩家画像和输赢统计必须有访问控制、变更记录和查询审计。
- 对外展示的统计应避免泄露个人隐私，不得用于公开羞辱、排斥或诱导玩家。

## 7. 验收要求

- 同一玩家在大厅和不同亲友圈中的统计结果相互独立。
- 关闭体验优化策略后，对局发牌和结算结果的分布不应发生变化。
- 所有策略命中必须有可审计的原因码，且不记录玩家手牌明细作为画像标签。
- 必须验证玩家画像无法调用或修改发牌、结算和回放核心模块。

## 9. 完整玩家体验计划架构

### 9.1 总体分层

```text
对局事件 -> 数据统计 -> 分域玩家画像 -> 体验策略引擎
                                              |-> 匹配与组桌
                                              |-> 教学与引导
                                              |-> 活动与展示
                                              |-> 复盘与召回

隔离测试房 -> 测试场景编排器 -> 固定种子/指定牌序/机器人强度
                                    |-> 测试报告与审计日志

公平性门禁 -> 隔离体验策略与发牌、结算、回放核心模块
```

### 9.2 分域数据层

- 大厅使用 `scope_type=hall` 和唯一大厅 `scope_id`。
- 亲友圈使用 `scope_type=club` 和对应 `club_id`，每个亲友圈独立统计。
- 基础事件包含：开局、发牌、操作、托管、离开、结算、重新开局和举报。
- 聚合结果包含：场次、净得分、胜率、波动率、连胜连败、大小牌倾向、激进度、稳健度、托管率和离开率。
- 建议核心数据对象：`player_scope_stats`、`player_style_profile`、`experience_action_log`和 `test_scenario_audit`。

### 9.3 画像层

- 水平标签：新手、熟练、进阶，仅用于匹配和教学。
- 出牌风格：保守、均衡、激进，使用可解释的历史指标生成。
- 当前状态：正常、连败、疲劳、高退出风险，用于提示和房间推荐。
- 所有标签设置版本、有效期和生成原因，防止永久固化玩家。

### 9.4 体验策略引擎

- 组桌策略：优先将水平接近、延迟接近、当前所在统计域一致的玩家组桌。
- 新手策略：给予规则提示、出牌建议、复盘和明示陪练机器人选项。
- 连败策略：推荐更匹配的房间、休息提示、教程和战绩复盘，不修改牌局。
- 激进玩家策略：提供风险提示和对局数据回顾，不使用诱导性奖励扩大损失。
- 每次策略输出必须包含 `strategy_id`、`strategy_version`、`reason_code`、生效范围和过期时间。

### 9.5 测试发牌与好牌场景

此模块只用于隔离测试房，用于复现局面、压力测试和验证表现：

- 固定种子：相同版本和种子必须产生相同牌序。
- 指定手牌：可为测试座位设置强牌、弱牌、特定牌型或残局。
- 胜率模拟：通过批量机器人对局验证规则、策略和牌型的统计分布，不通过调整真人手牌达成目标胜率。
- 机器人强度：分为教学、标准和压力三档，通过决策质量调节，不偷看未知牌。
- 场景存档：记录 `scenario_id`、`game_code`、规则版本、种子、初始手牌、预期验收点和创建人。

### 9.6 测试隔离与发布门禁

- 仅测试账号可进入，房间内和战绩页必须持续显示“测试牌局”。
- 必须同时命中测试构建、服务端测试环境和测试房标识才能启用。
- 服务端拒绝正式账号、正式房间或无权限账号传入的牌序和种子参数。
- 正式构建不包含测试发牌入口、路由、按钮和运行时开关。
- 每次创建、修改、执行和删除测试场景均写入不可篡改审计日志。

### 9.7 效果评估

- 核心指标：次日留存、七日留存、完局率、中途离开率、重新开局率和举报率。
- 公平性指标：随机数分布、牌型分布、座位胜率、规则版本差异和异常发牌告警。
- 评估方式：小流量灰度、对照组、固定观察周期和预先定义的停止条件。
- 策略评估只比较匹配、教学、提示和展示效果，不以操控玩家输赢作为成功指标。

### 9.8 实施阶段

1. 第一阶段：建立分域事件、玩家统计和数据审计。
2. 第二阶段：上线可解释玩家画像、匹配和新手引导。
3. 第三阶段：建立隔离测试房、场景编排器、固定牌序和机器人压测。
4. 第四阶段：建立公平性检测、异常告警、灰度评估和发布门禁。
